점검 대상: 기존 프로젝트(Streamlit + FAISS/BM25 RAG). 처음부터 다시 만들지 않고 점검·수정했습니다.
표기: **[검증]** 실행·테스트로 확인 / **[코드]** 코드 읽기로만 확인 / **[미검증]** 확인하지 못함.

## 4. 검색 실험 (Phase 4)

조건: 답변 가능·라벨 있는 52문항, (자료, 쪽) 단위 관련성, 5회 반복 지연시간 중앙값, macOS. 부트스트랩 95% 신뢰구간.

| 구성 | Recall@5 | MRR@5 | 지연(ms) |
|---|---|---|---|
| **BM25 (채택)** | **0.900** | 0.878 | 0.4 |
| BM25 + 의도 앵커(승격) | 0.916 | 0.878 | 0.4 |
| 의미 검색만 | 0.617 | 0.576 | 14.3 |
| 하이브리드 | 0.893 | 0.886 | 14.4 |
| 하이브리드 + 재정렬 | 0.887 | 0.891 | 14.7 |
| RRF | 0.846 | 0.812 | 14.5 |

- 하이브리드 − BM25 = −0.007 (CI −0.062~0.041): **차이 없음**. 의미 검색만 − BM25 = −0.283 (유의하게 낮음). RRF, 재정렬, 청크 크기(600/1100/1800), 문맥 헤더: 유의한 이득 없음(`experiment_*.csv`).
- 이득이 확인된 개선: **질의 불용어 제거**(Recall@5 0.77 → 0.89 당시 측정), FAQ 문항 단위 청킹.
- **주의:** 같은 52문항을 보며 규칙을 다듬었으므로 수치는 개발 집합 성능입니다(낙관적). 의도 앵커는 사용자가 요청한 6문항을 맞추기 위해 승격 방식으로 유지했고, 평균 이득은 유의하지 않습니다.
- 최종 구성: BM25 + 질의 불용어/조사 처리 + 학번 필터 + 의도 앵커 승격, 청크 1100/120, Top-5, 재정렬·의미 검색 없음. 의미 검색은 `RETRIEVAL_BACKEND=auto`로 선택 사용.
